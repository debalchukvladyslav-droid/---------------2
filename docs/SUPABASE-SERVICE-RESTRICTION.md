# Supabase: відповіді 402 через ліміти

`Service for this project is restricted` та `exceed_*_quota` означають
обмеження проєкту платформою. Зміна пароля, очищення браузера чи запит до
іншої таблиці не відновлюють сервіс. Позначка `ACTIVE_HEALTHY` у Management
API не виключає обмеження Data API.

## Відновлення доступу

1. Власник організації перевіряє [використання ресурсів](https://supabase.com/dashboard/org/tsihnxpputoirybwrzxa/usage)
   та [налаштування тарифу](https://supabase.com/dashboard/org/tsihnxpputoirybwrzxa/billing).
2. На Free негайне зняття обмежень передбачає перехід на Pro. На Pro зі
   Spend Cap можна вимкнути обмеження витрат, погодившись на оплату перевищення.
   Spend Cap доступний лише на Pro.
3. Для збереження Free потрібно зменшити обсяг бази та Storage до квот і
   врахувати вже використаний трафік поточного розрахункового періоду.
   Видалення файлів не скидає використаний egress. Квоти трафіку поновлюються
   на початку наступного періоду; зняття обмежень може мати затримку.
4. Після зняття обмежень перевірити `public_team_names`, вхід за ніком,
   завантаження журналу та синхронізацію відкладених змін.

Джерела: [HTTP 402](https://supabase.com/kb/troubleshooting/http-status-codes),
[Fair Use Policy](https://supabase.com/docs/guides/platform/billing-faq#fair-use-policy),
[Spend Cap](https://supabase.com/docs/guides/platform/cost-control#spend-cap).

## Діагностика 29 жовтня 2026

Перевірено через Management API, SQL та серверні логи:

- Організація `Kofer org`, проєкт `Trader Journal Pro`, тариф Free.
- База: 2277 MB; найбільші таблиці `data_recovery.change_history` — 1558 MB,
  `data_recovery.restore_points` — 432 MB.
- Storage: `screenshots` — 1491 MB / 6731 об'єкт,
  `journal-backups` — 843 MB / 275 об'єктів.
- Серверні фонові завдання теж отримують 402.

Це виміри обсягу на момент перевірки, а не повна статистика білінгу або egress.
Запити були лише для читання. Дані, файли, історія та резервні копії не видалялися;
тариф і Spend Cap не змінювалися.

Перед будь-яким скороченням історії чи резервних копій перевірити незалежну
резервну копію за [OFFSITE-BACKUPS.md](OFFSITE-BACKUPS.md). Скорочення історії
синхронізації також потребує узгодженого оновлення курсорів клієнтів.

На клієнті `js/supabase_errors.js` розпізнає обмеження навіть без поля HTTP
статусу. Вхід за ніком не переходить до `profiles` після такого збою; екран
входу й помилка запуску показують причину українською. Ручна повторна спроба
залишається доступною після відновлення сервісу.
