# Виправлення за звітами 6–12 жовтня 2026

Переглянуто всі 33 надані файли. Вони описують чотири типи помилок; багато файлів містять console та unhandledrejection для тієї самої події.

| Помилка | Причина та виправлення |
| --- | --- |
| `DATA_LOSS_GUARD` під час збереження | Невивірені таблиці прибиралися з повного settings snapshot, що означало їх видалення для merge patch. Тепер до успішної звірки лишаються кешовані таблиці. При повторному завантаженні скидаються ознаки завантажених колекцій, а всі settings payload застосовуються через спільну функцію. Захист від справжнього масового очищення збережений. |
| `JWT expired` під час запуску | Завантаження профілю оновлює сесію й повторює запит один раз. Якщо сесія більше недійсна, показується форма входу. Після зміни акаунта старий запит не повторюється. |
| Drive `Unauthorized` | Список і завантаження файлів використовують спільний запит з одноразовим оновленням сесії після 401. Повторна авторизація та відсутній доступ до папки мають різні повідомлення. |
| OCR `importScripts` network error | Tesseract.js 5.1.1, worker, обидва LSTM core та English language data постачаються з сайту. Один worker обслуговує всі зони зображення та завершується у `finally`. Параметри OCR задаються через `setParameters`. Збій OCR зберігає попередній тікер; запізнілий результат не перезаписує інший акаунт або новіше ручне редагування. |

Запізнілі settings та sheet reads також перевіряють акаунт і поточний об'єкт даних перед застосуванням відповіді. Аудит імпортів тепер перевіряє наявність і залежності спільних файлів у `lib/`, що усуває хибні blocking issues.

## Перевірено

- `npm.cmd run validate`: 531 тест, 531 успішний, 0 помилок; синтаксис, partials і аудит успішні. Додано 12 регресійних тестів. В існуючому тестовому оточенні settings додано відсутній об'єкт `window`.
- `git diff --check`: без помилок пробілів.
- Edge: гостьовий запуск `/`, `/calendar`, `/screen`, `/stats` під CSP з `vercel.json`, без помилок JavaScript.
- Реальний OCR у браузері з заблокованим CDN: SIMD та non-SIMD core розпізнали `AAPL TSLA NVDA`, confidence 92. Worker, core і language data завантажувалися з localhost.
- Реальний IndexedDB у браузері: повторні settings saves під час незавершеної звірки зберегли обидві таблиці, змінили тему та дозволили очищення двох колекцій скрінів; у черзі синхронізації не було видалень таблиць. Зовнішні запити Supabase у цій перевірці заблоковані.

## Межі

Зміни внесені в локальну робочу копію й ще не розгорнуті на публічному сайті. Дані чинних користувачів у Supabase та Drive не змінювалися. Повний вхід і синхронізація з живими зовнішніми сервісами не перевірялися; відновлення сесії перевірене регресійними тестами з контрольованими відповідями.

Локальні журнали перевірки: `.recovery/bugfix-final-validation.log`, `.recovery/bugfix-browser-result.json`, `.recovery/bugfix-storage-browser-result.json`.
