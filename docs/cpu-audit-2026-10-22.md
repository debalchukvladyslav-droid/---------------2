# Vercel CPU audit — 22 October 2026

The owner reports **4h 12m of Fluid Active CPU** for `trader_journal`, 12 minutes above the ordinary 4-hour Hobby allowance. The public domain is `traderjournal-six.vercel.app`; the separate project named `traderjournal-six` has different domains.

Historical CPU ranking could not be read through the current Hobby API: the metrics endpoint returns `payment_required` (Observability Plus), and the billing usage endpoint has no data for this free subscription. Recent runtime logs show activity on `trader_journal`, with Sheets reads and a Telegram lookup. Log counts are not CPU measurements, so they do not establish the monthly cause.

## Changes

- Load ExcelJS when constructing an XLSX export, instead of loading it whenever the Sheets API starts.
- Load the SHS, client-error and service-bot handlers only for their respective routes. Public configuration and server time no longer initialize those integration modules.
- Load the criteria and Telegram handlers only for the relevant trade API routes.
- Reuse fixed timezone formatters for market dates and Telegram dates, instead of constructing one for each record and requested day.

Authentication, response formats, trading calculations, cron schedules and resource limits are unchanged.
